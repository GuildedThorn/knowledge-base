## Purpose

Rewrite the vr-brain Earth "from the bottom up" for the highest fidelity practical in Godot 4 C#, with a pluggable data-layer framework so any geospatial dataset can be added, usable on both desktop and VR. Decided 2026-07-24.

## Summary

Two parts, built together:
1. **Cube-sphere planet engine** — from-scratch, chosen over draped-slippy-tiles (poles) and 3D-Tiles/Cesium-ion (dependency/billing). Real orbit-to-surface, WGS84, real terrain relief.
2. **GeoLayer framework** — decouple data *Source* from render *Layer* (Cesium/deck.gl model). Every feature (ADSB, NWS, radar, winds, heat, cyber, WiGLE, pins, quakes, fires) is a `IGeoLayer` on the globe. This is the backbone that makes "much more" trivial.

**Decisions:** render core = cube-sphere from scratch. API keys = free-tier OK (WiGLE, abuse.ch Auth-Key, OpenWeatherMap, Mapbox — pasted into `vr-brain.cfg`). First data layers = all four groups (weather, cyber, winds+heat, natural events). Refs: [High-Fidelity Planet Rendering (Godot)](kb://06-reference-high-fidelity-planet-rendering-godot), [Globe Data Source APIs](kb://06-reference-globe-data-source-apis).

## Architecture

- **`Geo`** — WGS84 constants; `Vector3d`; geodetic↔ECEF (Bowring); lat/lon↔unit-dir (keeps existing texture convention so pins align); cube→sphere COBE warp.
- **`CubeSphere`** — builds a per-face cube-sphere `ArrayMesh` (COBE-warped, equirect UVs, normals). Base for the LOD quadtree. Also builds the shared streamed-tile grid (`BuildTileGrid`, added 2026-07-24 — see Phase 4).
- **`GeoGlobe`** (replaces `Earth` internals; keeps its public API as a drop-in) — cube-sphere surface with per-face **chunked-LOD quadtree** driven by screen-space error `SSE = geomError·H/(dist·2tan(fovy/2))`; per-chunk streaming imagery (GIBS/EOX free); **floating-origin + rescaled units** for precision (Godot `precision=double` is unusable in C#); hull-sphere atmosphere scattering; UTC subsolar sun + day/night + night lights. Exposes `IGeoGlobe` (SurfaceRoot, LatLonToLocal, RadiusMeters, RequestGoto) + hosts `GeoLayerManager` + shared clock.
- **`IGeoLayer` / `GeoLayerManager`** — `OnAdd/OnRemove/Process/Pick`, visibility/z-order, data-driven styling. Sources fetch on worker threads → queue → main-thread apply (existing discipline), query by bbox+zoom+time.
- **Interaction** — one unified model for desktop mouse + VR controllers: hover→pick→act, trackball rotate, dive-zoom, god's-eye grab. Comfort: miniature god's-eye globe, teleport/snap-turn (godot-xr-tools).
- **MCP** — keep `earth_pin`/`earth_pins`; add `earth_goto`, `earth_layer` (toggle/list).

## Roadmap

- **Phase 0 — Foundation ✅:** `Geo.cs`, `Vector3d.cs`, `CubeSphere.cs`, `GeoLayer.cs` framework. Compiles; old Earth kept running.
- **Phase 1 — Cube-sphere renderer ✅ (core):** cube-sphere base mesh swapped in for the UV sphere (`CubeSphere.BuildGlobe`), pole-correct + uniform density; `earth.gdshader` now samples imagery per-fragment from surface direction (no seam, topology-independent); sun-aware scattering atmosphere (`atmosphere.gdshader`, blue lit-limb → orange terminator → faint night, fed world-space sun). Existing streaming imagery + layers unchanged and working. **Precision insight:** the globe is a *miniature* object in the constellation, not true-scale — so **floating origin is unnecessary** (absolute coords stay small, no jitter), and the chunked-LOD quadtree's payoff is terrain relief, so it moves to Phase 4.
- **Phase 2 — Framework wiring ✅ (core):** `Earth` implements `IGeoGlobe` + hosts `GeoLayerManager` (process/pick/toggle, `_ExitTree` cleanup). MCP tools `earth_goto` (fly-to, frames a place from outside + faces it via `XRRig.GotoLookAt`) and `earth_layer` (list/on/off) added. **Fixed:** cube-sphere back-face winding (terrain was invisible from outside — culled — while fine from inside); verified from orbit. Still TODO: port legacy pins/aircraft/threats onto the framework; unified pick→hover readout; settings-panel toggles.
- **Phase 3 — New layers:** Four archetypes proven & verified live from orbit — **polygons** (`WeatherAlertsLayer`, NWS ✅), **points** (`QuakesLayer`, USGS pulsing ✅), **rasters** (`RadarLayer`, NEXRAD WMS ✅), **arcs** (`CyberThreatLayer`, DShield top-attacker IPs → GeoLite2 → animated attack-map arcs, no key ✅). **Global flights ✅:** Flights got a `[flights] mode` — `global` (OpenSky `/states/all` worldwide, optional free OAuth2 creds `opensky_client_id/secret`, ~1500-cap) or `radius` (adsb.lol). Perf: global's 1500 contacts thrashed the GPU via per-plane trail meshes (→20 fps); fixed by auto-disabling trails in global mode + capping visible labels to 80 (→145 fps). **Future scale:** move darts to `MultiMesh` for thousands.
- **Phase 3 layers — COMPLETE (8 live, all verified from orbit):** weather_alerts, quakes, radar, cyber_threats (DShield + optional Feodo), fires (FIRMS, needs `[firms] map_key`), wigle (needs `[wigle] api_name/token`), wind (Open-Meteo global streaks ✅), heat (GIBS LST shell ✅, off by default — toggle via earth_layer). Key-gated layers self-disable cleanly ("layer idle") until keys are pasted. `heat.gdshader` added (direction-sampled shell). ~93 fps with everything on; per-layer toggles via `earth_layer` MCP tool.
- **Phase 4 — Fidelity + polish:** **Terrain relief ✅** — AWS Terrarium elevation (no key) displaced onto the detail tiles: `[earth] terrain_layer/terrain_exaggeration(=5, fixed)/terrain_max_zoom`. Fixed (zoom-independent) exaggeration so LOD neighbours agree on edge heights (per-zoom exaggeration tore black cracks). `earth_goto` arrives oblique so relief reads.
  - **Hill-shading ✅** (`terrain_tile.gdshader`, rewritten 2026-07-24): shading normal now comes from a **fragment-space central difference of the displaced position**, sampled straight from the per-tile heightmap texture at full resolution — not per-vertex on the tile's coarse mesh. Sun fed via a **global shader uniform** `earth_sun_obj`. Gentle contrast so per-texel normal noise stays faint.
  - **Caching/perf ✅:** raw tiles disk-cached (verified 0 re-downloads on revisit); **in-memory processed-DEM cache** (filter once, reuse across shared ancestors + rebuilds); patch subdivision 24→16; fetch concurrency 6→12. `DrainTiles` build budget raised 4→16/frame (2026-07-24) now that building a tile is a texture upload, not a mesh rebuild (see below).
  - **Render distance ✅ (2026-07-26):** the streaming-activation altitude gate in `UpdateTiles` — above which detail + 3D-terrain tiles tear down to the flat base texture — was a hardcoded `radius * 0.6`. Now the config key `[earth] detail_render_radius` (default **1.2**, clamp 0.3–4.0, via `DefaultDetailActiveRadius`/`_detailActiveRadius`), so real terrain relief renders from a further / higher vantage. Paired with `[earth] detail_grid` **5 → 9** (the widest supported tile ring, clamp 1–9) for more terrain area streamed per view. This is the heaviest combo — if near-surface FPS dips, pull `detail_render_radius` back toward 0.9 first (bigger cost than the grid width). Build clean (0 warnings/errors); takes effect on next Earth load. The independent decor-hide gate (`zBase >= _detailMaxZoom - 3`) is unaffected.
  - **Applied 2026-07-24** (see [Terrain Rendering Optimization](kb://06-reference-terrain-rendering-optimization) and the "Code Rewrite — Earth Tile LOD" entry in [vr-brain Improvement Areas](kb://00-inbox-vr-brain-improvement-areas)), fixing a real hole/pop-while-zooming bug: **vertex-shader displacement from a per-tile height texture on a shared grid mesh** (`Geo.CubeSphere.BuildTileGrid`, one mesh reused by every tile — `BuildTilePatch` is now a texture+uniform upload, not a `SurfaceTool` rebuild); **imagery/terrain decouple + parent-upsample fill-tiles** (`CreatePlaceholderTile` — a newly-needed tile instantly points at a resident ancestor's textures via cropped UV sub-rects, so the old tile can be evicted the same frame with nothing left blank); a **CDLOD-style morph** (blends the height sample toward a coarser heightmap mip near the refine threshold — a practical analogue for a texture-displaced grid, not a literal port of Strugar's clipmap vertex morph). Needs in-headset confirmation (build is clean, rendering not yet visually verified).
  - **Still NOT applied**: 1-px **neighbour-apron edge stitching** (removes the faint tile grid at its source — the DEM 1-px mismatch; skirts still hide it visually for now); **request prioritisation** (`(1−dot)·dist`, cancel off-frustum — today's screen-space-error priority queue already refines nearest/largest-on-screen first, deferred since it wasn't implicated in the reported symptom).
- **Non-terrain remaining (optional):** settings-panel toggle rows per layer (today via `earth_layer` MCP); port legacy pins/aircraft/threats onto the framework; `MultiMesh` darts (thousands); Hillaire scattering; MSAA/VRS-XR + xr-tools comfort; hover-to-read on layers.

## Testing

- **`scenes/EarthTest.tscn` (added 2026-07-24):** standalone desktop harness — just the globe + a free-fly camera (`src/Tools/FreeFlyCam.cs`) + a lat/lon/altitude/FPS/layer-status HUD (`src/Tools/EarthTestMain.cs`). No VR rig, no other constellation subsystems, so terrain/tile bugs can be visually verified from a plain desktop window instead of needing a headset or the full app. Run: `nix develop -c godot --path . scenes/EarthTest.tscn`.
- **Bugs found/fixed via the test client (2026-07-24):**
  - `Earth._Ready()` called `RenderingServer.GlobalShaderParameterGetList()` to check if `earth_sun_obj` was already registered — that call is editor-only and logged "should never be used outside the editor, it can severely damage performance" on every launch (including the full app, launched the same way). Fixed: replaced with a static `_sunParamRegistered` bool.
  - **Pins/markers/title disappearing:** `UpdateTiles()`'s decor-hide check was gated on `alt > radius*0.6` — the same broad threshold that turns the streaming-tile system on at all — so decor vanished the moment the camera got within 60% of the globe's radius, long before anything was actually zoomed to street level (the original intent). Fixed: gated on `zBase >= _detailMaxZoom - 3` instead (the real LOD depth already computed for tile selection), so decor now only hides once genuinely close-in, and reappears immediately on pulling back. Confirmed fixed live in the test client.

## Investigated — Google Earth 3D mesh API (2026-07-24, prototype in progress)

Scoped whether [retroplasma/earth-reverse-engineering](kb://06-reference-google-earth-3d-photogrammetry-api-kh-google-com) (Google Earth's undocumented `kh.google.com/rt/` photogrammetry API — real textured terrain+building meshes, not a heightmap grid) could replace/augment the AWS Terrarium terrain pipeline. Endpoint confirmed still live 2026-07-24 despite the reference client being archived since 2022.

Per the original recommendation (small offline decode prototype before any real engineering time, kept out of vr-brain proper), built **`~/Documents/EarthRt`** — a standalone project spawned from [vr-base](kb://07-projects-vr-brain-vr-brain-overview)'s `new-project.sh` template, not a vr-brain module. Status and how to resume: [Google Earth 3D Photogrammetry API (kh.google.com)](kb://06-reference-google-earth-3d-photogrammetry-api-kh-google-com) — prototype builds clean, fetches and parses `PlanetoidMetadata` correctly (hand-verified byte-for-byte against a real response), but the octree walk into `BulkMetadata` still hits a parse desync partway through a response before a full mesh has been rendered and visually confirmed. **Verdict unchanged: the real blocker is ToS/stability, not effort** — this stays a side prototype, not a path onto the vr-brain trunk.

## Config (planned `[earth.*]` / per-layer sections in vr-brain.cfg)

Free keys: `[wigle] api_name/api_token`, `[abuse_ch] auth_key`, `[owm] api_key`, `[mapbox] token`. Each layer: `enabled`, refresh, source-specific params. Center/home shared with `[flights]`/`[threat]`.

**Render-distance tuning (`[earth]`):** `detail_render_radius` (default 1.2, clamp 0.3–4.0) = altitude, as a fraction of the globe's world radius, below which detail + 3D-terrain tiles stream in; above it the flat base texture is used. `detail_grid` (default 5, clamp 1–9) = width of the N×N tile ring loaded around the focus point. Raise both for more terrain from further out; both cost GPU/bandwidth, `detail_render_radius` more so.
